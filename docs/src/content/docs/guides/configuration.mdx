# Configuration

ryu_ldn_nx can be configured via a configuration file on your SD card. The config file is auto-generated with defaults on first boot.

## Configuration File

The configuration file is located on the SD card at:

```
sdmc:/config/ryu_ldn_nx/config.ini
```

On a PC, this appears as `config/ryu_ldn_nx/config.ini` on the SD card root.

If the file doesn't exist, the sysmodule creates it automatically with default values on first boot.

## Reference Configuration

```ini
; ryu_ldn_nx Configuration
; Auto-generated on first boot

[server]
; Relay hostname (empty = do not connect)
host =
; Server port
port = 443
; Secure WebSocket transport (plain TCP is refused)
transport = wss
path = /ldn
console_id =
; Secret: 64 hex characters, one per console
token =
ca_file = sdmc:/config/ryu_ldn_nx/ca.pem

[network]
; Connection timeout in milliseconds
connect_timeout = 5000
; Ping interval in milliseconds (parsed but not used — server drives pings)
ping_interval = 10000
; Initial reconnect delay in milliseconds (fast retry of 200ms applies first attempt)
reconnect_delay = 3000
; Max reconnect attempts (0 = disable auto-reconnect, not infinite)
max_reconnect_attempts = 5

[ldn]
; Enable LDN emulation (0/1/true/false/yes/no)
enabled = 1
; Room passphrase (empty = public)
passphrase =
; Network interface (empty = auto)
interface =
; Disable P2P proxy (0/1/true/false/yes/no)
disable_p2p = 1

[debug]
; Enable debug logging (0/1/true/false/yes/no)
enabled = 0
; Log level (0=errors, 1=warnings, 2=info, 3=verbose)
level = 1
; Log to file (0/1/true/false/yes/no)
log_to_file = 0

[perf]
; NOT IMPLEMENTED — these settings are NOT parsed and NOT consumed.
; They have no effect. Kept as comments for future reference only.

; enable_larger_socket_buffers = 0
; socket_recv_buffer_kb = 64
; socket_send_buffer_kb = 64
; enable_bg_thread_high_priority = 0
; bg_thread_priority = 8
; enable_tight_drain_loop = 0
; recv_timeout_ms = 20
; bg_thread_sleep_ms = 10
; enable_manager_mutex_release = 0
; enable_async_send_queue = 0
```

## Boolean Values

Boolean config keys accept more than just `0` and `1`. The parser checks only the **first character** of the value:

- **`false`**: `0`, `f`, `F`, `n`, `N` (and any string starting with these, e.g. `false`, `False`, `no`, `No`)
- **`true`**: Anything else (`1`, `true`, `yes`, `y`, etc.)

This means `true`, `True`, `yes`, `Yes`, `1` all evaluate to **true**, while `false`, `False`, `no`, `No`, `0` evaluate to **false**. Be careful — invalid values like `2` or `hello` also evaluate to **true**.

## Sections

### `[server]` — Server Connection

| Option | Default | Description |
|--------|---------|-------------|
| `host` | *(empty)* | Relay hostname. Empty means the sysmodule does not connect |
| `port` | `443` | Relay port |
| `transport` | *(empty)* | Must be `wss` (TLS WebSocket). Missing, empty or anything else refuses to connect; plain TCP is not offered |
| `path` | `/ldn` | WebSocket path on the relay |
| `console_id` | *(empty)* | Sent as `X-Console-Id`: `a-z`, `0-9`, `-`, 1 to 32 characters |
| `token` | *(empty)* | Sent as `Authorization: Bearer`: exactly 64 hex characters, anything else is rejected. Never logged or shown in the overlay |
| `ca_file` | `sdmc:/config/ryu_ldn_nx/ca.pem` | PEM trust anchors (at most 64 KB) that the relay certificate must chain to; the hostname is checked too |

With `transport = wss`, `disable_p2p` is forced to `1`.

```ini
[server]
host = relay.example.com
transport = wss
console_id = living-room
token = <64 hex characters>
```

### `[network]` — Connection Behavior

| Option | Default | Description |
|--------|---------|-------------|
| `connect_timeout` | `5000` | TCP connection timeout in milliseconds |
| `ping_interval` | `10000` | ⚠️ Parsed but **not used** — server drives keepalive pings |
| `reconnect_delay` | `3000` | Initial reconnect delay in milliseconds |
| `max_reconnect_attempts` | `5` | Max reconnect attempts (0 = **disable auto-reconnect**, not infinite) |

The reconnect system uses a **fast first retry** (200ms for the first attempt only) before switching to exponential backoff starting at `reconnect_delay` (default 3s, with 2x multiplier and 30s cap) with ±10% jitter. TCP keepalive is enabled automatically (30s idle / 10s interval / 5 probes).

**Note on `ping_interval`**: This key is parsed and stored in config but **not consumed** by the network client — the server drives keepalive pings. Changing this value has no effect.

**Note on `max_reconnect_attempts`**: A value of `0` **disables** auto-reconnect entirely (the client will not retry after the first failure). For unlimited retries, set a very large number.

### `[ldn]` — LDN Emulation

| Option | Default | Description |
|--------|---------|-------------|
| `enabled` | `1` | Enable/disable LDN emulation. Read each time a game starts Local Wireless; `0` leaves games on real local wireless |
| `passphrase` | _(empty)_ | Room passphrase for private rooms (empty = public) |
| `interface` | _(empty)_ | Parsed but **not used** — always auto-detects network interface |
| `disable_p2p` | `1` | Disable P2P proxy (0=enable P2P, 1=relay only) |
| `real_wireless_button` | `ZR` | Button held **while launching** a game for real local wireless on that launch (see below) |

#### Online or real local wireless

No overlay is needed to choose. Each time a game starts Local Wireless, the sysmodule picks:

- **Online (server)** by default.
- **Real local wireless** when the console has no network connection, since the server cannot be reached anyway.
- **Real local wireless** for the whole launch when you **hold the real-wireless button (ZR by default) while starting the game** (keep holding until the game starts loading, like Atmosphère's hold-R for the homebrew menu). Pressing it later, once the game is running, does nothing: Atmosphère reads the buttons only at launch. Use this to play with an unmodded Switch in the same room.
- **Real local wireless** when `enabled = 0`.

`real_wireless_button` picks that button. Names (case-insensitive): `A` `B` `X` `Y` `L` `R` `ZL` `ZR` `PLUS` `MINUS` `LSTICK` `RSTICK` `DLEFT` `DUP` `DRIGHT` `DDOWN`. Join them with `+` for a combo that must all be held, for example `ZL+ZR`. `none` turns the button off. A value that cannot be read keeps `ZR` and logs a config warning.

Avoid `L` and `R`. Atmosphère reads them at launch too: holding **L** starts the game without LayeredFS mods and cheats, and holding **R** opens the homebrew menu instead of the game. They are accepted (with a config warning) in case you changed Atmosphère's keys. `ZL` and `ZR` have no Atmosphère launch meaning, and neither alone opens the Ultrahand or Tesla overlay menu.

Setting `disable_p2p = 1` forces relay mode through the server. This is more reliable for most setups but adds server load. Enable P2P (`disable_p2p = 0`) if UPnP port mapping works on your network — it allows direct peer connections and reduces latency.

### `[debug]` — Logging

| Option | Default | Description |
|--------|---------|-------------|
| `enabled` | `0` | Enable debug logging (0=off, 1=on) |
| `level` | `1` | Log level: 0=errors, 1=warnings, 2=info, 3=verbose |
| `log_to_file` | `0` | Write logs to `config/ryu_ldn_nx/ryu_ldn_nx.log` (0=off, 1=on) |

Log levels:
- **0** — Errors only (critical issues)
- **1** — Warnings (potential problems, **default**)
- **2** — Info (normal operation events)
- **3** — Verbose (detailed debug, including packet traces)

At verbose level (3), the log can grow quickly. Read deltas per test run rather than the full file.

### `[perf]` — Performance Tuning (Not Implemented)

> **Warning**: The `[perf]` section keys are **NOT parsed** by the INI parser and **NOT consumed** by the runtime. They are commented out in the example config and included only as reference for future implementation. Changing them has **zero effect**.

These keys are reserved for future use:

| Option | Description |
|--------|-------------|
| `enable_larger_socket_buffers` | Bump socket receive/send buffers to reduce backpressure |
| `socket_recv_buffer_kb` | Socket receive buffer size in KB |
| `socket_send_buffer_kb` | Socket send buffer size in KB |
| `enable_bg_thread_high_priority` | Raise LDN background thread priority |
| `bg_thread_priority` | Thread priority (lower = higher priority) |
| `enable_tight_drain_loop` | Reduce drain loop latency |
| `recv_timeout_ms` | Receive timeout in the tight drain loop |
| `bg_thread_sleep_ms` | Sleep between drain iterations |
| `enable_manager_mutex_release` | Early mutex release in ProxySocketManager |
| `enable_async_send_queue` | Asynchronous send queue for BSD MITM |

## Applying Changes

After modifying `config.ini`:

1. Save the file
2. Use "Force Reconnect" in the Tesla overlay, or
3. Reboot your Switch

Some settings (like `[server]` host/port) require a reconnect. Debug `enabled` and `level` take effect immediately when changed through the overlay (or after a config reload). Edits made directly to `config.ini` are only picked up on reload or reboot.

Boolean values must be `true`, `false`, `1` or `0` (any case). Anything else (`yes`, `off`, an empty value) is ignored, the default is kept, and a warning is logged.

## Overlay Configuration

You can also view and modify some settings through the Tesla overlay:

1. Open Tesla Menu (L + DPad Down + Right Stick)
2. Select "ryu_ldn_nx"
3. Toggle debug mode or force reconnect

See [Using the Overlay](/ryu_ldn_nx/guides/overlay) for more details.
